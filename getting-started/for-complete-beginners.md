# 完全开发小白：你到底怎么开始

先说结论：**不要一上来改那些开源大仓库。**  
你的第一目标不是「做出 Timefold 级别的自动排班」，而是：

> 用最笨的办法，做出一个能给 10～20 个坐席排下周班的小工具。

开源仓库是「参考书」，不是「你家装修要搬进来的整栋楼」。

---

## 0. 你需要先接受的三件事

1. **排班系统 = 业务系统**，编程只是手段。业务没想清，代码会越写越乱。
2. **自动求解是加分项**，手工排班后台才是地基。一线现场很多团队第一年都在用 Excel。
3. **你会卡很久，这很正常。** 目标是每周有一个能演示的小进展，不是三个月做出携程同款。

---

## 1. 开始前：先不当程序员，当产品经理（1～3 天）

在纸上或飞书文档写清楚（可以很糙）：

### 必须回答的问题
- 排给谁？几个组？大概多少人？
- 班次有哪些？（如：早 9–18、中 11–20、晚 14–23、夜班……）
- 技能怎么分？（机票 / 酒店 / 签证 / 双语 / 只做在线？）
- 最小时间粒度？（建议先用「半天/整班」，别一上来 15 分钟）
- 哪些绝对不能破？（连上 6 天、夜班间隔、未成年/实习限制等）
- 谁发布班表？一线能否换班？

### 产出物（没有这些不要写代码）
- 一张「角色清单」：管理员 / 班组长 / 坐席
- 一张「班次模板表」
- 三五条「硬规则」+ 三五条「尽量满足的软规则」

---

## 2. 编程基础：只学马上用得到的（2～4 周，可并行）

你不需要先成为全栈工程师。建议二选一：

### 路线 A（更推荐小白）：Python
- 学：变量、列表、字典、读写 CSV/Excel、写一个简单网页（可用 Streamlit）
- 为什么：和 mod_turbotab、roster-wizard、OR-Tools 生态近
- 第一成果：上传「员工表 + 班次表」，页面上拖/选完成周排班，能导出 Excel

### 路线 B：TypeScript / 网页
- 学：HTML/基础 JS、一个前端框架入门、简单后端 API
- 为什么：以后做正式后台更自然
- 第一成果：同上，但是网页日历形态

**每天 1～2 小时即可。** 不要同时学 Java + Python + React。

配套学习（任选平台）：
- Python 官方教程 / 廖雪峰 Python
- 《SQL 必知必会》级入门（会建表、增删查改）
- Git 只学：clone、add、commit、push（够用）

## 3. 你的第一个真正项目（MVP-0，再花 2～4 周）

名字可以叫：`我的第一版排班表`

### 功能只要这 5 个
1. 维护员工（姓名、组别、技能标签）
2. 维护班次模板（名称、开始结束时间）
3. 按「周」给员工分配班次（先手工点选）
4. 检查冲突：同一人同一天两个班；技能不够则标红
5. 导出 Excel / 打印给组长

### 明确不做
- 不做 Erlang、不做自动求解、不做换班审批、不做 App
- 不做登录也行（本机自己用）

### 数据可以先用 Excel
- `employees.csv`
- `shifts.csv`
- `assignments.csv`

能跑通，你就已经超过「只收藏 GitHub 星标」的 90% 人。

## 4. 开源仓库怎么读（重要）

错误方式：把 StaffScheduler 整个 clone 下来，幻想改两下就能用。  
正确方式：

1. 只打开 README，抄它的**模块名词**（员工、班次、赋值、发布）
2. 看它的**数据表/模型名字**，对照你自己的 CSV
3. 遇到自动求解、Docker、复杂权限——**先跳过**

精读顺序建议：
1. 先读本仓库 `references/comparison.md`
2. 产品壳对照：StaffScheduler 或 employee-shift-scheduler 的 README
3. 有余力再打开 mod_turbotab 试算一组假话务

---

## 5. 什么时候才进入「自动」

当你的手工版已经在真实小组试用 ≥ 2 周，再考虑：

1. **接需求层**：用历史话务（或组长拍脑袋的预测）+ Erlang 算出「每班要几人」
2. **接求解层**：用 OR-Tools / Timefold 生成初稿，人再改
3. **再做登录、权限、换班、审计**

跳级的代价通常是：三个月后什么也演示不了。

## 6. 你可以怎么用我（这个助手）

适合让我帮你做的：
- 把你的业务规则整理成「表结构 + 接口清单」
