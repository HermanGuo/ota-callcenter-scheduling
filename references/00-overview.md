# 四层架构总览

OTA 呼叫中心排班，建议按下面四层理解开源项目。每一层解决不同问题，**不要指望一个仓库覆盖全部**。

```
[预测话务量] → [A. 算每时段要多少人] → [B. 自动把人排进班次] → [C. 产品壳：发布/换班/休假]
                      ↑                        ↑
                 Erlang / shrinkage      Timefold / OR-Tools
                                                      ↕
                                         [D. 日内重排 / 端到端小样]
```

## 各层在 OTA 一线的含义

| 层 | 你要回答的问题 | 典型输入 | 典型输出 |
|----|----------------|----------|----------|
| A 人力需求 | 今天下午 14:00–14:30 要多少人在线才够 SLA？ | 预测话务、AHT、目标服务水平 | 每 15/30 分钟的「需求人数」 |
| B 自动排班 | 谁上早班/晚班/夜班，技能是否匹配？ | 需求曲线、员工技能、劳动法约束 | 一份可行班表 |
| C 产品壳 | 班表怎么维护、发布、换班审批？ | 组织、坐席、班次模板 | Web 后台 / 日历 |
| D 日内 / 小样 | 中午突然航变高峰，怎么临时补洞？ | 实时话务、当前在岗 | 缺口看板 / 临时调整建议 |

## 怎么用这份资料

1. 先看 [comparison.md](comparison.md) 选 2～3 个精读。
2. 零基础开发顺序看 [../getting-started/for-complete-beginners.md](../getting-started/for-complete-beginners.md)。
3. 不要一上来 fork 全部仓库；**读思路、抄模块、自己写第一版**。
